# 設備点検アプリ 引き継ぎ資料

野田組の設備点検を紙からデジタル化するプロジェクト。Google Apps Script（GAS）のウェブアプリとして構築中。

## 全体構成

- **バックエンド**: Googleスプレッドシート（設備マスタ + 設備区分ごとの点検記録シート）
- **フロントエンド**: GASのウェブアプリ（`doGet` + HtmlService）。QRコード経由で `?eq=設備ID` を付けて開くと、その設備の点検フォームが直接開く
- **PDF自動生成**: 月末に、元Excelの様式（結合セル・書式そのまま）をテンプレートとしてコピーし、点検結果を書き込んでPDF化する仕組み（時限トリガーで毎月1日 朝6時に実行）

## 既知の未対応・要確認事項

1. **コンプレッサの既存データの誤り**: 点検区分フィルタ機能を実装する前に送信された記録は、本来「日常」の2項目だけ入力すべきところ、全項目（3か月/1年/2年含む）が誤って「○」で保存されている。「コンプレッサ点検記録」シートを開き、該当行の対象外列を手動で空欄にする必要がある（自動修正スクリプトは未実装）。
2. **月次PDFのテンプレートシート未整備の可能性**: `書式_溶接機`, `書式_クレーン`, `書式_局所排気`, `書式_コンプレッサ`, `書式_リフト` の5シートを、元Excelファイルから「シートのコピー→他のスプレッドシート」でこのスプレッドシートにコピーする作業をユーザーに依頼済みだが、完了確認が取れていない。未完了ならPDF生成時に「書式テンプレートが見つかりません」エラーになる。
3. **PDFのタイトル部分は自動更新されない**: `generateMonthlyPDF` はテンプレートをコピーして点検結果のマスだけ埋める方式のため、コピー元シートに残っている「◯年◯月分」「自◯月◯日〜至◯月◯日」等のタイトル文字列は書き換わらない。月が変わるたびに手動修正が必要、または追加実装が必要。
4. **写真アップロード機能は未実装**: スプレッドシートに「写真」列はあるが、フォーム側に画像アップロードのUIはまだない。

### 解消済み

- **QRコード発行**: 「QRコードを発行する」画面で、登録済み設備ごとに点検フォーム（`?eq=設備ID`）へのQRコードを一覧表示・印刷できるようになった（`getEquipmentQrList` / `renderQrList`）。
- **点検項目そのものを追加する機能は削除済み**: 一時期「点検項目を増やす」画面（`addInspectionItem` / `renderAddItem`）を実装したが、これは要望を誤解したもの（本来の要望は「同系統の設備を増やす」＝既存の「設備を新規登録」機能）だったため削除した。
- **既存項目のPDF出力先は`PDF行設定`シートで管理**: 上記の誤った機能を作る過程で、月次PDFの行位置指定の仕組み（`PDF行設定`シート、`setPdfRowMapping_` / `getPdfRowMap_`）自体は、既存項目のPDF行ズレ修正（後述）に使う実用的な基盤として残してある。新規項目追加のUIは無い。
- **溶接機の複数項目が1マスを共有する問題に対応**: `書式_溶接機`では「作業環境」の2項目、「溶接装置」の4項目がそれぞれ同じ1行（1マス）を共有しており、1項目=1マスに分解できなかった。「1つでも✕なら✕、それ以外で1つでも○があれば○、全て該当なしなら該当なし」というルールを採用し、`generateMonthlyPDF`側で同じ行を共有する項目をグルーピングして1つの値にまとめて書き込むよう対応（`PDF行設定`シートで意図的に同じ行番号を複数項目に割り当てている）。`Setup.gs`の`backfillPdfRowMappings()`にこの6項目分も追加済み（再実行すればOK。既存の登録は上書きされる）。
- **既存設備（設備マスタ）の情報を編集できるように**: 「設備情報を編集する」画面から、設備名・管理番号・設置場所・部署・責任者・点検頻度・備考を編集できるようになった（`updateEquipment` / `renderEditEquipmentList` / `renderEditEquipmentForm`）。設備ID・設備区分は点検記録シートとの紐付けに使うため編集不可。
- **設備選択を「区分→個別設備」の2段階に変更**: 以前は登録済み設備を1枚のフラットな一覧で表示していたが、まず溶接機・クレーン・局所排気装置・コンプレッサ・リフトの**区分**を選び、その区分の中の**個別設備**（例: 溶接機なら EW-794/EW-784/EW-681）を選ぶ2段階の一覧に変更した（`loadPicker`が区分一覧、`renderCategoryEquipment`が個別設備一覧）。あわせて、以前はQRコード（`?eq=設備ID`）で開くとその設備の点検フォームへ直接ジャンプしていたが、`init()`が常に区分選択（`loadPicker()`）から始まるように変更した。`?eq=`パラメータ自体は`doGet`側にまだ残っているが、現在この初期表示の分岐には使われていない。
- **既存項目のPDF行ズレを一部修正**: 実際のテンプレートを1行ずつ数え直し、クレーン10項目と溶接機3項目（ホルダー・ケーブル・責任者表示）について正しい行番号を特定。`Setup.gs`の`backfillPdfRowMappings()`を一度だけGASエディタから実行すると、`PDF行設定`シートに登録され、以降の月次PDFで反映される。局所排気装置・コンプレッサはテンプレートが元々1項目=1行の連番だったため、修正不要（今まで通り正しく動く）。
- **リフトの月次PDFが常に失敗するバグを修正**: `書式_リフト`テンプレートには「1,2,3…」という日付の数字が無く「日」という文字が並んでいるだけだったため、`findDayHeader_`が日付ヘッダーを見つけられず`generateMonthlyPDF('LF-01', ...)`が常にエラーになっていた。
  - 最初に作った`fixLiftTemplateDayHeader()`（列の自動追加＋数字書き込み）は、「点検日」行と「作業前点検項目」行で有効列数の数え方がズレるバグがあり、実際に列崩れを起こしたため**削除した**。
  - 代わりに、**列の追加はSheets上で手動で行い**（該当行を右クリック→列を挿入）、**数字の書き込みだけ**を行う安全な`setLiftDayNumbers()`に置き換えた。列の追加・削除は一切行わないため、構造を壊すリスクが無い。31列分の空きができた状態で実行すること。
  - 副作用として、「点検日」「作業前点検項目」の**両方**の行に1〜31の数字が入ると、`findDayHeader_`（シートを上から走査して最初に見つかる「1,2が隣り合う行」を日付ヘッダーとする）が、より上にある「点検日」行を日付ヘッダーとして検出してしまう（本来使いたいのは1行下の「作業前点検項目」）。そのため実際の点検項目1行目はheadから2行下にずれる。この分は`backfillPdfRowMappings()`にリフト15項目分（行オフセット2〜16）を追加して補正済み。`書式_リフト`の実物のレイアウトを変えた場合は、このオフセットも見直すこと。

## デプロイ方法

**手動デプロイのみ**（GitHub Actionsによる自動デプロイは廃止）。

GitHub Actions経由での自動デプロイ（`clasp login`の個人認証をCIで使う方式）を試みたが、Google Workspace組織のセキュリティポリシーにより、無人環境からのログインが`invalid_grant`（reauth required）エラーで拒否されるため断念した。回避策としてサービスアカウント認証も検討したが、組織ポリシーでサービスアカウントの鍵作成自体が制限されており、設定作業が煩雑なため見送った。

反映手順（このフォルダで実行）:

```bash
git pull origin claude/equipment-inspection-app-3glfyc
clasp push --force
```

`.clasp.json` に既にスクリプトID（上記参照）が設定済みなので、`clasp login` さえ済んでいれば追加設定は不要。
