# 設備点検アプリ 引き継ぎ資料

野田組の設備点検を紙からデジタル化するプロジェクト。Google Apps Script（GAS）のウェブアプリとして構築中。

## 全体構成

- **バックエンド**: Googleスプレッドシート（設備マスタ + 設備区分ごとの点検記録シート）
- **フロントエンド**: GASのウェブアプリ（`doGet` + HtmlService）。QRコード経由で `?eq=設備ID` を付けて開くと、その設備の点検フォームが直接開く
- **PDF自動生成**: 月末に、元Excelの様式（結合セル・書式そのまま）をテンプレートとしてコピーし、点検結果を書き込んでPDF化する仕組み（時限トリガーで毎月1日 朝6時に実行）

## 既知の未対応・要確認事項

1. **コンプレッサの既存データの誤り**: 点検区分フィルタ機能を実装する前に送信された記録は、本来「日常」の2項目だけ入力すべきところ、全項目（3か月/1年/2年含む）が誤って「○」で保存されている。「コンプレッサ点検記録」シートを開き、該当行の対象外列を手動で空欄にする必要がある（自動修正スクリプトは未実装）。
2. **月次PDFのテンプレートシート未整備の可能性**: `書式_溶接機`, `書式_クレーン`, `書式_局所排気`, `書式_コンプレッサ`, `書式_リフト` の5シートを、元Excelファイルから「シートのコピー→他のスプレッドシート」でこのスプレッドシートにコピーする作業をユーザーに依頼済みだが、完了確認が取れていない。未完了ならPDF生成時に「書式テンプレートが見つかりません」エラーになる。
3. **PDFのタイトル部分は自動更新されない**: `generateMonthlyPDF` はテンプレートをコピーして点検結果のマスだけ埋める方式のため、コピー元シートに残っている「◯年◯月分」「自◯月◯日〜至◯月◯日」等のタイトル文字列は書き換わらない。月が変わるたびに手動修正が必要、または追加実装が必要。
4. **溶接機の一部項目は、紙の様式上そもそも1項目=1マスに分解できない（実物確認済み）**: `書式_溶接機`テンプレートを1行ずつ実際に数えたところ、「作業環境_引火物爆発物可燃物なし」「作業環境_整理整頓されている」の2項目が同じ1行に、「溶接装置_本体スイッチ類の損傷なし」「溶接装置_カバー類の損傷なし」「溶接装置_接続箇所の緩みなし」「溶接装置_確実に作動する」の4項目が別の同じ1行に、それぞれ結果を書き込む列が1つしか無い状態で同居している。この6項目は、複数の項目の結果（○/✕/該当なし）のうち何を優先してその1マスに書くかのルールを決めないと自動化できない（例:「1つでも✕なら✕」等）。ルールが決まれば`generateMonthlyPDF`側に反映可能。それ以外の3項目（ホルダー・ケーブル・責任者表示）と、クレーンの10項目は1項目=1行に分離できることを確認し、`Setup.gs`の`backfillPdfRowMappings()`で`PDF行設定`シートに登録済み（1回だけGASエディタから実行する必要あり、下記参照）。
5. **リフトの月次PDFは現状ほぼ確実に失敗する（実物確認済み・今回新たに発見）**: `書式_リフト`テンプレートには「1,2,3…」という日付の数字が無く、「日」という文字が並んでいるだけ。`findDayHeader_`は数字の1と2が隣り合うセルを探す実装のため、リフトのテンプレートでは絶対に見つからず、`generateMonthlyPDF('LF-01', ...)`は毎回「テンプレート内に日付ヘッダーが見つかりません」エラーで失敗する。テンプレート側の該当行に実際の日付数字（1〜31）を入れる修正が必要（点検項目を増やす機能の対象外の、既存の別バグ）。
6. **写真アップロード機能は未実装**: スプレッドシートに「写真」列はあるが、フォーム側に画像アップロードのUIはまだない。

### 解消済み

- **QRコード発行**: 「QRコードを発行する」画面で、登録済み設備ごとに点検フォーム（`?eq=設備ID`）へのQRコードを一覧表示・印刷できるようになった（`getEquipmentQrList` / `renderQrList`）。
- **点検項目の追加**: 「点検項目を増やす」画面から、スプレッドシートを直接編集せずに、同じ設備区分の全設備に新しい点検項目（列）を追加できるようになった（`addInspectionItem` / `renderAddItem`）。コンプレッサ等「点検区分」を持つ区分では、対象の区分（日常/3か月/1年/2年）も指定する。
- **新規追加項目のPDF出力先を指定可能に**: 「点検項目を増やす」画面に「PDFテンプレートの行番号（任意）」欄を追加。`書式_◯◯`シートの日付ヘッダー行を1行目として、結果を書き込みたい行が何行下かを入力すると、新設の`PDF行設定`シート（設備区分・項目名・行番号を記録）に保存され、`generateMonthlyPDF`がその行に直接書き込むようになった（`setPdfRowMapping_` / `getPdfRowMap_`）。空欄のままならこれまで通りPDFには出力されない。
- **既存項目のPDF行ズレを一部修正**: 実際のテンプレートを1行ずつ数え直し、クレーン10項目と溶接機3項目（ホルダー・ケーブル・責任者表示）について正しい行番号を特定。`Setup.gs`の`backfillPdfRowMappings()`を一度だけGASエディタから実行すると、`PDF行設定`シートに登録され、以降の月次PDFで反映される。局所排気装置・コンプレッサはテンプレートが元々1項目=1行の連番だったため、修正不要（今まで通り正しく動く）。

## デプロイ方法

`.github/workflows/deploy-gas.yml` により、このフォルダ配下（`equipment-inspection-app/`）への変更を `claude/equipment-inspection-app-3glfyc` ブランチにpushすると、GitHub Actionsが自動で `clasp push` を実行し、実際のGASプロジェクトに反映する。

初回セットアップとして、リポジトリの Settings → Secrets and variables → Actions で `CLASPRC_JSON` という名前のSecretを登録する必要がある（値は自分のPCで `clasp login` した後の `~/.clasprc.json` の中身）。
